# Plan 09-01: Reestruturação Gradle, Migração 100% Kotlin/Compose & Pipeline Híbrida

## Phase Context
- **Goal:** Reorganizar a estrutura de pastas para o padrão Gradle (`app/`), refatorar a bridge C++ JNI, migrar a UI do Launcher inteiramente para Kotlin + Jetpack Compose (removendo código Java legado), extrair recursos e atualizar a pipeline de compilação híbrida (Gradle AGP + Termux CLI).
- **Requirements:** [RESTRUCT-01, JNI-01, KOTLIN-01, BUILD-02]
- **Target Files:**
  - `settings.gradle`
  - `build.gradle`
  - `app/build.gradle`
  - `build_termux.sh`
  - `src/launcher/shizuku_layer_injector.cpp`
  - `src/launcher/gimi_native_bridge.cpp`
  - `app/src/main/java/com/gimi/launcher/MainActivity.kt`
  - `app/src/main/java/com/gimi/launcher/jni/GimiNativeBridge.kt`
  - `app/src/main/java/com/gimi/launcher/jni/ModInfo.kt`
  - `app/src/main/res/values/strings.xml`
  - `app/src/main/res/values/colors.xml`

---

## Tasks

### Task 1: Reorganizar Estrutura de Diretórios para Padrão Gradle (`app/`)
- Mover o diretório `android/app/` para `app/` na raiz do repositório.
- Atualizar `settings.gradle` na raiz do projeto para definir `include ':app'` diretamente (em vez de `include ':android:app'`).
- Ajustar os caminhos relativos em `CMakeLists.txt` e `app/build.gradle` para refletir a nova localização do módulo `:app`.

### Task 2: Limpar Stubs C++ em `shizuku_layer_injector.cpp` e Atualizar JNI Bridge Nativa
- Simplificar `src/launcher/shizuku_layer_injector.cpp`, removendo chamadas de comandos `system()` obsoletos/duplicados e mantendo apenas a lógica limpa de injeção Shizuku IPC.
- Atualizar a assinatura e bindings JNI em `src/launcher/gimi_native_bridge.cpp` para alinhar com o pacote Kotlin `com.gimi.launcher.jni.GimiNativeBridge` (métodos nativos: `nativeInjectLayer`, `nativeCheckStatus`, `nativeExtractMod`, etc.).

### Task 3: Migrar UI do Launcher para 100% Kotlin + Jetpack Compose & Deletar Código Java Legado
- Substituir o `MainActivity.java` imperativo (que usava Views/XML) por `MainActivity.kt` utilizando Jetpack Compose (`ComponentActivity`, `setContent`, `MaterialTheme`).
- Integrar as telas Compose existentes (`DashboardScreen.kt`, `ModManagerScreen.kt`, `SettingsScreen.kt`, `GimiApp.kt`) com a navegação `NavGraph.kt`.
- Confirmar e consolidar as classes de dados Kotlin `GimiNativeBridge.kt` e `ModInfo.kt` sob o pacote `com.gimi.launcher.jni`.
- Extrair strings harcoded da interface para `app/src/main/res/values/strings.xml` e paleta de cores para `app/src/main/res/values/colors.xml`.
- Excluir definitivamente os arquivos Java legados: `MainActivity.java`, `GimiNativeBridgeJava.java`, `ModInfoJava.java` e `ModInfo.java`.

### Task 4: Atualizar Configurações Gradle (`app/build.gradle`) e Script Termux (`build_termux.sh`)
- Em `app/build.gradle`:
  - Adicionar plugins do Gradle: `id 'com.android.application'` e `id 'org.jetbrains.kotlin.android'`.
  - Configurar `buildFeatures { compose true }` e `composeOptions { kotlinCompilerExtensionVersion '1.5.8' }` (ou versão compatível).
  - Incluir dependências necessárias do Compose Material 3, Navigation Compose e Lifecycle.
- Em `build_termux.sh`:
  - Atualizar os caminhos relativos de `android/app` para `app`.
  - Incluir a compilação de fontes Kotlin (`kotlinc`) e empacotamento de arquivos `.class` gerados pelo Kotlin no arquivo `classes.dex` via `d8`.
  - Garantir suporte ao fallback transparente `gradle assembleDebug` tanto em ambiente x86_64 quanto em Termux ARM64.

### Task 5: Compilação, Verificação do Build e Geração do APK Assinado
- Executar `bash build_termux.sh` e `gradle assembleDebug`.
- Verificar se a compilação de fontes C++ e Kotlin é concluída sem avisos ou erros.
- Garantir a geração do APK assinado e funcional `GIMI-Launcher.apk` / `app-debug.apk`.
- Validar as assinaturas do APK através de `apksigner verify` ou `aapt2 dump badging`.

---

## Verification Strategy
- **Verificação da Estrutura:** Confirmar que `app/src/main` existe e que `android/app` foi removido/migrado.
- **Verificação do Compilador:** Executar `bash build_termux.sh` garantindo término com código de saída 0.
- **Validação de Legado:** Garantir que nenhum arquivo `.java` permaneça em `app/src/main/java/`.
- **Assinatura do APK:** Confirmar presença e validação limpa da assinatura no APK final gerado.
