# Plan 08.5-01: Correção de Permissões Android e Refatoração de Injeção

## Objective
Resolver as limitações de permissão do Android que impedem a leitura de arquivos e a injeção da Vulkan Layer. Em vez de usar comandos C++ `system()`, vamos solicitar e verificar permissões através das APIs nativas do Android no `MainActivity.java`.

## Tasks

1. **Permissão de Storage (Mods List)**
   - Editar `MainActivity.java` para verificar `Environment.isExternalStorageManager()`.
   - Se for falso, iniciar um Intent `ACTION_MANAGE_APP_ALL_FILES_ACCESS_PERMISSION` redirecionando o usuário para conceder acesso total ao armazenamento, garantindo que o C++ possa escanear `/sdcard/GIMI/Mods`.

2. **Permissão WRITE_SECURE_SETTINGS e Injeção Niva (Java)**
   - No AndroidManifest.xml, adicionar `<uses-permission android:name="android.permission.WRITE_SECURE_SETTINGS" tools:ignore="ProtectedPermissions" />`.
   - Em `MainActivity.java`, criar o método `boolean hasSecureSettingsPermission()` que checa se a permissão foi concedida.
   - Refatorar a lógica de injeção em Java: em vez de depender de `GimiNativeBridge.injectLayer(...)` que usa `system()`, implementar a escrita do `Settings.Global.putInt(...)` e `Settings.Global.putString(...)` diretamente na activity Java se a permissão estiver concedida.
   - Se a permissão não estiver concedida, alterar a mensagem do botão "INJECT VULKAN LAYER" para instruir o usuário a rodar o comando ADB/Shizuku no computador ou terminal (`adb shell pm grant com.gimi.launcher android.permission.WRITE_SECURE_SETTINGS`).

3. **Validação da Layer**
   - Atualizar a detecção do status da layer no `DashboardViewModel.kt` para usar Java `Settings.Global.getString(contentResolver, "gpu_debug_layers")` em vez do C++ call lento/bloqueado, determinando corretamente se "libgimi_arm64.so" está ativo.

4. **Remoção de Código C++ Legado**
   - No `shizuku_layer_injector.cpp`, limpar os métodos que falhavam tentando usar `system()`.
