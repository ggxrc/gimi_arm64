# Plan 02-01: Parser de configurações `.ini` C++ e estruturas de dados de mod

**Phase:** Phase 2: Parser de Configurações 3dmigoto & Gestão de Hashes
**Requirement(s):** CFG-01, CFG-03
**Goal:** Implementar o parser C++ de arquivos `.ini` do 3dmigoto (Orfix.ini, Txfix.ini e overrides) e as estruturas de dados `ModDatabase` que indexam as regras de substituição por hash para consulta O(1) durante o render.

## Context

O 3dmigoto utiliza arquivos `.ini` com seções nomeadas (`[TextureOverride.*]`, `[ShaderOverride.*]`, `[Resource.*]`, `[Constants]`) para declarar regras de substituição de recursos gráficos. O parser desta fase constrói a `ModDatabase` — a estrutura que o Resource Replacement Engine da Fase 3 consultará a cada draw call. **Nenhuma leitura de arquivo deve ocorrer durante frames de render**: tudo é pré-carregado na inicialização.

Biblioteca base: **`inih`** (C header-only, zero dependências externas, compila limpo no NDK r26b+).

## Tasks

### Task 1: Integrar `inih` como third-party header-only
- **Goal:** Disponibilizar a biblioteca `inih` no projeto sem dependências externas.
- **Files to create/modify:**
  - `third_party/inih/ini.h` *(copy do repositório oficial)*
  - `third_party/inih/ini.c` *(copy do repositório oficial)*
  - `CMakeLists.txt` *(adicionar `third_party/inih` como include dir e fonte)*
- **Details:**
  - Copiar somente os dois arquivos essenciais (`ini.h` + `ini.c`) do repositório `benhoyt/inih`.
  - Adicionar ao `CMakeLists.txt` como source compilada junto da `libgimi_arm64.so`.
  - Alternativa: usar a versão C++ (`INIReader`) se o build do NDK suportar — preferir a versão C pura para garantir compatibilidade.

### Task 2: Definir estruturas de dados `ModDatabase` e tipos de regras
- **Goal:** Declarar em C++ todos os tipos que representam regras do 3dmigoto.
- **Files to create/modify:**
  - `include/config/mod_types.h`
- **Details:**
  - `struct TextureOverrideRule { uint32_t hash; std::string resource_name; /* ps-t0..tN slot, etc. */ }`
  - `struct ShaderOverrideRule { uint32_t hash; std::string shader_resource; }`
  - `struct ResourceDeclaration { std::string name; std::string filename; /* type: buffer|texture */ }`
  - `struct ConstantRule { std::string name; std::string value; }`
  - `struct ModDatabase` contendo mapas indexados por hash/nome:
    - `std::unordered_map<uint32_t, TextureOverrideRule> texture_overrides`
    - `std::unordered_map<uint32_t, ShaderOverrideRule> shader_overrides`
    - `std::unordered_map<std::string, ResourceDeclaration> resources`
    - `std::vector<ConstantRule> constants`

### Task 3: Implementar `IniParser` (wrapper C++ sobre `inih`)
- **Goal:** Classe C++ que carrega um arquivo `.ini` (ou conjunto de arquivos via `$include`) e popula uma `ModDatabase`.
- **Files to create/modify:**
  - `include/config/ini_parser.h`
  - `src/config/ini_parser.cpp`
- **Details:**
  - `IniParser::load(const std::string& path, ModDatabase& db)` — carrega o arquivo, interpreta seções e chama os handlers correspondentes.
  - Suporte à diretiva `$include <filename>` — ao encontrar no valor de qualquer chave raiz, carrega recursivamente o arquivo referenciado relativo ao diretório base.
  - Normalização de chaves: case-insensitive (converter para lowercase antes de comparar).
  - Hash parsing: aceitar strings hex de 8 dígitos (ex: `a1b2c3d4`) e converter para `uint32_t` via `std::stoul(hash_str, nullptr, 16)`.
  - Tratamento de erros gracioso: seções/chaves desconhecidas são ignoradas com `LOGW`; arquivos ausentes geram `LOGE` mas não travam o carregamento.

### Task 4: Instanciar e expor `ModDatabase` via singleton `ModConfig`
- **Goal:** Ponto de acesso global à `ModDatabase` carregada, inicializado durante `graphics_dispatcher_init()`.
- **Files to create/modify:**
  - `include/config/mod_config.h`
  - `src/config/mod_config.cpp`
- **Details:**
  - `ModConfig::load(const std::string& mods_dir)` — varre o diretório de mods, carrega todos os `.ini` encontrados na raiz usando `IniParser`.
  - `ModConfig::instance()` — singleton de acesso à `ModDatabase` populada.
  - Diretório de mods padrão: `/sdcard/gimi_mods/` (configurável via constante de compilação `GIMI_MODS_DIR`).
  - `graphics_dispatcher.cpp` deve chamar `ModConfig::load(GIMI_MODS_DIR)` durante `init()`.

---

## Verification Criteria

1. Um arquivo `.ini` de exemplo contendo `[TextureOverride.*]`, `[ShaderOverride.*]` e `[Resource.*]` é parseado corretamente para a `ModDatabase` sem erros.
2. Hashes em formato hex de 8 dígitos (`a1b2c3d4`) são convertidos corretamente para `uint32_t`.
3. Arquivos ausentes ou seções desconhecidas geram logs de aviso mas não travam o carregamento.
4. A diretiva `$include` carrega arquivos auxiliares (ex: Txfix.ini) sem recursão infinita.
5. `ModConfig::instance().db().texture_overrides` contém as entradas esperadas após `load()`.
